# 动效组件选型

先看用户目标、现有组件和 `package.json` / `components.json` / 样式方案；保留项目已有的设计语言和动画依赖。用户指定的库优先，除非实际版本或授权不允许。

## 最短路径

- 简单 hover、淡入和状态反馈：先考虑 CSS 或现有组件能力；不为一个小动效引入新库。
- 需要布局过渡、拖拽、手势或编排：优先考虑项目已有的 Motion；如已安装官方 `$motion` skill，仅按需加载其**相关一节**，否则查当前官方文档。不要通读全部参考资料。
- 需要现成组件：只在此时阅读 [组件选型表](references/catalog.md)，按用途、技术栈、风格、授权筛到 1–2 个候选；查看候选组件的当前官方页面和依赖，再选一个。
- 复杂滚动叙事：考虑 GSAP；它是动画引擎，不是现成 UI 组件库。

避免同时安装多个库来解决同一个效果。付费组件仅在项目已有授权或用户同意后使用。实现时检查键盘、焦点、触屏、`prefers-reduced-motion`、性能与响应式；有实际界面时检查渲染结果。回复只说明选用组件和关键理由，除非用户要求完整比较。
